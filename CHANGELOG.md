## 0.2.0

- Added `AppVersionGate`/`GateDecision`/`AppVersionGateConfig`/`evaluateVersionGate`/`compareAppVersions`/`AppVersionGateController` (FEAT-59): soft/force update and maintenance-mode gating from remote config, with a fully safety-first policy — any invalid input (an unparseable current version, or an unparseable `minimumVersion`/`recommendedVersion`) degrades to `GateDecision.ok` rather than ever force-blocking a user for a corrupt config; only a plain `maintenanceActive` bool (can't be "invalid") can force/maintenance-gate. `compareAppVersions` documents its own semver policy: prerelease sorts before the same core release (`1.2.3-beta` < `1.2.3`), build metadata (`+001`) is ignored entirely. `AppVersionGateController` reads straight from `RemoteConfigService` rather than keeping its own cache — that service already gives "asset default, remote merges in, remote fail/corrupt keeps last-good" for free (`ENH-58`). Ships `AppVersionGateOverlay`: force/maintenance block the back button (`PopScope(canPop: false)`) and aren't dismissible; soft update is dismissible and reports back via `onSoftDismiss` so the caller can persist the cooldown; a failed injected `launchStore` call shows an inline error and a "Retry" button instead of looping. Demoed in `WidgetShowcaseScreen`.
- Added `DeepLinkCommandRouter`/`DeepLinkRoute`/`DeepLinkCommand`/`parseDeepLink` (FEAT-60): parses deep links into typed commands against an allowlist of routes (scheme/host/path shape — a `:name` path segment captures a param) and dispatches them to registered handlers, with no concrete deep-link plugin dependency — a consuming app feeds its own URI stream (e.g. `app_links`) into `handleUri`. `parseDeepLink` is a pure function (fixture-testable) that rejects an oversized URI, an unrecognized scheme/host, or a path that matches no route — never throws. A link arriving before `markReady()` is queued (never dropped) and drains exactly once when the app signals it's ready; a duplicate call for the same URI within `dedupeCooldown` is ignored, deterministically even for 2 concurrent calls (the cooldown is stamped before any handler awaits). Every handler registered for a command type runs (highest `registerHandler` priority first) even if an earlier one throws — captured per-entry in a diagnostic `DeepLinkHandlerResult`, never rethrown, and never affecting a different command's dispatch. Demoed in `WidgetShowcaseScreen` and wired into the example app's real `AndroidManifest.xml` intent-filter (`roycasualkit://open/...`) via `app_links`.
- Added `ConnectivityCoordinator`/`ConnectivitySignal`/`ConnectivityState`/`QueuedTask` (FEAT-62): a reactive Internet-reachability coordinator with a bounded, idempotent retry queue. `ConnectivityState.online` is reported **only** once an injected `probe` (e.g. a HEAD request to a known-good endpoint) actually succeeds — a `ConnectivitySignal` reporting a network interface is up is never, by itself, treated as online (a captive portal or DNS outage would otherwise false-positive). Interface flapping is debounced before evaluation, and a single failed probe while previously online moves to `ConnectivityState.degraded` rather than straight to `offline` (hysteresis) — only `failuresToGoOffline` consecutive failures declare it truly offline, so flapping connectivity can't spam the UI. `enqueue`d tasks are capped at `maxQueueSize` (evicts the lowest-priority entry once full), keyed by `idempotencyKey` (a duplicate replaces, never duplicates), and drain automatically once back online — highest priority first, through an injectable `RetryExecutor`/`RetryPolicy` (FEAT-35) per task; one task exhausting its retries is dropped without blocking the rest of the queue, and a mid-drain drop back offline stops the drain immediately, leaving the rest queued. `connectedStream` bridges directly into `NetworkStatusBanner.stream`. Timers use the same injectable `createTimer` seam as `CheckpointCoordinator`/`HapticChoreographer`, and `onClose()` cancels every timer/subscription — no leaks. Demoed in `WidgetShowcaseScreen` alongside a `FakeConnectivitySignal` test double.
- Added `ConsentStateService`/`ConsentCategory`/`ConsentStatus` (FEAT-61): an SSOT for privacy consent gating `analytics` and `personalization` (no `ads` category — this kit ships no ads mediation seam, a deliberate product decision from FEAT-02's rejection). **Default-deny**: a category never explicitly decided reads as `ConsentStatus.unknown`, never `granted`, and a corrupted or hand-edited persisted entry is dropped rather than coerced, so it also reads as unknown — never an accidental early unlock. `policyVersion` support: a category persisted under an older policy version reads back as `unknown` regardless of its prior decision, forcing a fresh review after a privacy-policy bump. `grant`/`deny`/`reset` persist immediately and take effect immediately within the same instance. Ships `ConsentGatedAnalyticsProvider`, a decorator over any real `AnalyticsProvider` that only forwards `logEvent` while analytics consent is granted — a consuming app registers it in place of its real provider so every call site automatically respects consent. Demoed in `WidgetShowcaseScreen`, including gating `ExperimentBucketingService`'s variant assignment behind personalization consent.
- Added `PersistentCooldownService`/`CooldownStatus`/`CooldownSnapshot` (FEAT-36): a keyed cooldown tracker (reward claim timers, booster reuse delays, PvP action gates, ...) that survives app restart and resists clock-rewind cheating — every read is computed lazily from `nowMsClamped()` against a persisted `key -> endMs` map, the same anti-cheat clamp `EnergyService`/daily rewards/streaks already use. There is deliberately **no timer of any kind** in the service, per-key or shared: N active cooldowns cost zero background timers, the same zero-timer design `EnergyService` already uses for its own regen math. `start`/`cancel` validate their input (empty key, non-positive duration) and persist immediately (not write-behind-buffered, since a missed write on kill would let a booster be reused for free); a corrupted or hand-edited per-key entry is dropped rather than trusted, so it reads as never-started instead of coercing into an early unlock. Ships `CooldownCountdownChip` (`presentation/widgets/common/`), a thin adapter over `CountdownChip` that takes plain `remaining: Duration` data (same convention as `EnergyBar`/`LevelSelectGrid` — widgets take data, the caller owns the GetX service) and renders nothing while a cooldown is ready.
- Added `DeprecationRegistry`/`DeprecatedApi`/`DeprecationStatus` (FEAT-85): a semver-aware deprecation tracker for the SDK's own public API lifecycle. Each `DeprecatedApi` entry pairs with a real `@Deprecated('...')` annotation on the code and adds structured, machine-checkable data an annotation string alone can't carry — `deprecatedInVersion`, `removeInVersion` (validated to always be after `deprecatedInVersion`), and a `migrationHint`. `DeprecationRegistry.checkAll(currentVersion)` reports each entry as `active` or `pastGrace` (removal-version boundary is inclusive); `pastGraceOnly` filters to just the ones that should already be gone. Ships with `tool/deprecation_check.dart`, a standalone `dart run` script that reads the package's own `pubspec.yaml` version and its own `kPackageDeprecations` list and exits non-zero once something is past its removal version — ready for a consumer or this repo's CI to wire in when they choose (not wired into `.github/workflows/ci.yml` by this change).
- Added `SdkHealthReport`/`HealthCollectorSpec`/`defaultHealthCollectors` (FEAT-39): a QA/support-facing diagnostic snapshot collector registry, safe to export/share by default. Each `HealthCollectorSpec` declares its own key **allowlist** — any key its `collect()` returns that isn't on that list is silently dropped (default-deny, not default-allow), so a copy-pasted `token`/secret field can't leak into a report a support person might screenshot. A collector that throws or exceeds its timeout only fails its own section (`_error`), never the rest of the report; string/list values are size-capped so a report can't balloon. `defaultHealthCollectors()` ships one collector per app/audio/performance/remoteConfig/replay-buffer module, each reporting `registered: false` (not an error) when that module isn't wired up in the consuming app. Wired into `DebugQaOverlay`'s existing debug/profile-only gate as a new "Health" tab.
- Added `RetryPolicy`/`RetryExecutor`/`RetryOutcome`/`RetryAttemptEvent` (FEAT-35): a reusable exponential-backoff-with-jitter retry for cloud save/config/analytics calls, so consumers stop hand-rolling delay loops. `RetryPolicy` is pure math (immutable, computed entirely in `double` microseconds so a huge attempt number clamps to `maxDelay` instead of overflowing); `RetryExecutor` runs the actual loop with injectable `delayFn`/`randomFn` (same seam-injection convention as `HapticChoreographer`'s `createTimer`), so tests drive it deterministically without real delays. `retryIf` lets a caller stop immediately on a non-transient error; `isCancelled` lets a caller abort mid-loop; the final failure's `cause`/`stackTrace` are always preserved, never swallowed.
- Added `SecureStorageAdapter`/`SecureStorage`/`FakeSecureStorageAdapter` (FEAT-40): a platform-neutral secure-storage seam (no concrete SDK pulled in — a consumer registers their own adapter, e.g. wrapping `flutter_secure_storage`) with no `Noop*` default on purpose, same reasoning as `PurchaseSeam` — silently no-op'ing a secret write would hide a real integration bug. `SecureStorage.read/write/delete/clear` add the typed `SdkResult` contract, key validation, and — critically — a clear typed failure when no adapter is registered rather than ever falling back to plain `StorageService`/SharedPreferences for something meant to be secret. `FakeSecureStorageAdapter` is an in-memory test double for consumer contract tests.
- Added `GameTimeController`/`GameClock` (FEAT-49): a gameplay clock kept separate from wall clock, so pause/slow-motion/replay never desyncs a game's own timers. `GameClock` is a pure, no-Flutter-dependency core (mirrors `PerformanceTierService`'s `FrameBudgetTracker` split) — `advance()` clamps a negative or huge (backgrounded-for-minutes) delta, applies `scale` (rejecting a non-finite/non-positive value without touching the existing scale), and supports an optional fixed-step accumulator for deterministic sub-stepping. `GameTimeController` bridges it to Flame's `update(dt)` loop via `tick()` and to Flutter via the `elapsed` `Rx`; when a `GameSessionController` is wired in, ITS pause state is the sole authority (no second, competing pause flag), so double pause/resume between systems can't happen.
- Added `CheckpointCoordinator` (FEAT-46): coalesces multiple game systems' state into one atomic, versioned save checkpoint on top of `StorageService` — one JSON blob under one key, so a commit can never be observably "half applied" across participants the way separate per-system keys could be if killed mid-sequence. `requestCheckpoint()` debounces frequent calls (position/score ticks) into one flush after a quiet window; `critical: true` cancels that debounce and flushes immediately. A `RoyLifecycleCoordinator` hook flushes immediately on backgrounding. Keeps the previous commit as a fallback generation — `restoreLatest()` tries the current commit first, then that fallback, so one corrupted write doesn't lose the whole checkpoint; a participant's `snapshot()` throwing (or a non-JSON-encodable aggregate) aborts the whole flush before anything is written, never a partial/mixed commit.
- Added `AsyncCommonButton` (FEAT-50): a `CommonButton` wrapper that drives itself through idle/loading/success/error around an async `onPressed` — the state machine `BackupRestorePanel` hand-rolled per-widget before this existed. Guards double-tap/re-entry, supports an optional `timeout`, auto-reverts to idle after `successDuration`/`errorDuration`, respects `NeonTheme.reducedMotion`.
- Added `RewardTransactionPipeline`/`RewardLine`/`RewardTransactionRecord`/`RewardSource` (FEAT-42): orchestrates a reward grant (ad/IAP/quest/daily-login) across multiple currency lines on top of `EconomyWallet`'s existing per-line idempotency — groups lines under one logical transaction id (each line gets its own derived wallet transaction id so 2 lines never collide), keeps a source-tagged persisted audit trail, and `resumePending()` finishes a multi-line grant interrupted mid-way. A post-commit analytics hook can never roll back an already-applied reward. Earn-only by design; `grantFromDailyQuest`/`grantFromDailyLogin`/`grantFromPurchase` are thin adapters over the generic `grant()`.
- Added `StorageService.eraseAll()`/`removeAllWithPrefix(prefix)` (IDEA-55/IDEA-56): `eraseAll()` names the classic "Reset progress" Settings action self-explanatorily instead of relying on the undocumented `importAll(const {})` trick; `removeAllWithPrefix` wipes every key starting with a prefix (e.g. one save slot's namespaced keys) via the same rollback-on-error `_replaceAll` path, and rejects an empty prefix (which would otherwise silently behave like `eraseAll` under a name that doesn't say so).
- Added `SaveSlotManager`/`SaveSlotMeta` (IDEA-56): manages multiple independent save slots (separate characters/profiles) on the same device — `createSlot`/`listSlots` (most-recently-played first)/`renameSlot`/`touchSlot` for metadata, `activeSlotId`/`setActiveSlot` for which slot is current, and `keyFor(slotId, suffix)` handing out a namespaced storage key for a caller's OWN `VersionedJsonStore` (this never defines the player-profile schema itself). `deleteSlot` removes a slot's metadata and every one of its namespaced keys via `StorageService.removeAllWithPrefix` — no leftover keys, and it becomes the new `activeSlotId: null` if it was the active one.
- Added `GameSessionController.maybe` (ENH-65): brings it in line with every other service in `lib/core/`.
- Added `loading` to `ShopItemCard` (ENH-66): forwarded straight to the "Buy" `CommonButton` (IDEA-53) — shows a spinner and blocks double-tap while an in-flight purchase is pending.
- Fixed `RemoteContentPack` treating a missing `schemaVersion` as "already current" (skipping `migrate` entirely) instead of "version 0" like `VersionedJsonStore` (BUG-37) — a live-ops content author forgetting the field could silently end up with stale content and no error.
- Added `OnboardingCoordinatorService` (IDEA-54): decides WHICH onboarding/tutorial flow (`registerFlow`, `nextEligibleFlow`) should run next and whether one has already been seen (`isFlowSeen`/`markFlowSeen`, monotonic per flow version) — the coordination layer this package's tutorial widgets (`TutorialSequence`, `SpotlightOverlay`, IDEA-35's JSON-authored flows) never had. Never renders anything itself or touches `BuildContext`/`Navigator` — only answers "which flow, if any, should run right now"; a caller still owns showing the actual UI. Bumping a registered flow's version makes it eligible again exactly once, independent of every other flow.
- Added `ReplayRecorder`/`ReplayCapsule`/`ReplayEvent`/`findFirstDivergence` (IDEA-42): a bounded ring-buffer recorder for gameplay/input events, packaged (with the session's RNG seed, built on FEAT-45's `SeededRandom`) into a versioned, optionally-signed `ReplayCapsule` a developer can import elsewhere to reproduce a bug that was hard to describe from a screen recording alone. `record()` is O(1) (a fixed-size circular buffer write, no I/O) so it's safe on a gameplay hot path; a corrupt/tampered/future-schema capsule is rejected outright (`null`, never throws) rather than partially trusted. `findFirstDivergence` compares 2 ordered outcome lists (a recorded session vs a fresh replay) and reports the first point they differ, with enough context to debug why. `DebugQaOverlay` gained a Replay tab (start/stop/export) wired to it.
- Added `SeededRandom`/`RandomSnapshot`/`CompiledWeightedTable`/`SeededRandomService` (FEAT-45): a deterministic, cross-platform-stable RNG — `SeededRandom` implements `dart:math`'s `Random` (so it's a drop-in source for `weightedRandomPick`/`List.shuffle`/anything else expecting a `Random`), but unlike it exposes its internal state via `snapshot()`/`SeededRandom.fromSnapshot` for exact resume, and uses hand-rolled 32-bit-safe arithmetic so the same seed + call sequence produces the same output on every Dart compile target (a naive 64-bit generator would silently drift between the VM and a web build). `SeededRandomService` derives independent, namespaced streams (`stream('loot')`, `stream('enemy_spawn')`, ...) from one root seed via FNV-1a, so one system calling its stream an extra time never shifts another system's sequence. `CompiledWeightedTable` pre-validates a loot table once instead of every `pick()` call. Also extracted `fnv1aHash` (previously private to `ExperimentBucketingService`) into its own `core/utils/fnv1a.dart` util now that a second caller needs it.
- Added `EconomyWallet.maybe`/`RoyLifecycleCoordinator.maybe` (ENH-60): the only 2 `GetxService`s in `lib/core/` that were missing the static `.maybe` getter every other service already has (same gap shape as ENH-19's `CloudSaveProvider` fix) — both were added after that sweep.

- `AudioManager.playSfx` gained a `duck` param (IDEA-45): when true, bgm volume automatically drops for the duration of that SFX and restores once it (and every other concurrently-playing ducked SFX) finishes — a counter (exposed read-only as `AudioManager.duckCount`, so a caller's own UI can show a "ducked" indicator), not a bool, so overlapping ducked SFX never leave bgm stuck quiet after only the first one ends. Restore isn't gated on `muted`, so muting mid-duck and unmuting later never leaves bgm stuck at the ducked volume.

- Added `AchievementService.onUnlock` and `AchievementUnlockListener` (IDEA-43): `onUnlock` is a broadcast `Stream<String>` firing exactly once per achievement id the moment `incrementProgress` pushes it from not-completed to completed (never from `register`, even if a newly-declared threshold is already retroactively met; never again on further increments). `AchievementUnlockListener` wraps a subtree and shows a `ToastBanner` for every unlock — the first widget in the kit to actually consume `AchievementService`, which previously had none.
- Added `RemoteContentPack<T>` (IDEA-37): a typed, signed remote content slot for live-ops content (level definitions, shop catalogs, event schedules) built on `RemoteConfigService`'s asset-fallback-then-fetch pattern, `VersionedJsonStore`'s schema-version `migrate`, and `save_integrity.dart`'s HMAC signing. `load()` always resolves from the bundled asset first — never network-gated — then a `fetchRemote` fetch (if supplied) refreshes `current` in the background once it resolves. A fetched envelope with a bad/missing signature, a future `schemaVersion`, or a shape `fromJson` can't read is rejected silently, keeping whatever content was already applied — never crashes, never applies unverified content. A pack with no `contentSecret` configured never trusts a signed envelope at all (no key to check it against).
- `DebugQaOverlay` gained a Playground tab (IDEA-39) alongside its existing read-only state dump — a QA tester/designer can live-preview a `CommonButton` with an adjustable label, variant, and color directly on-device (long-press the corner, switch tabs), no rebuild needed.
- Added `TrustedClockService`/`classifyClockSample` (IDEA-40): a rewind-proof clock that also RECOVERS from a suspicious forward jump, unlike `utils/clamped_clock.dart`'s plain watermark (which permanently locks onto a far-future jump — deliberate or an honest clock misconfiguration — until the real wall clock naturally catches up, which for a big jump can be months or years). Classifies each new `ClockSample` (wall + monotonic reading) as normal/rewind/suspiciousForwardJump/reboot; a rewind or a quarantined jump never advances the trusted baseline, so it stays comparable against reality instead of a bogus reading. Migrates from the legacy `StorageKeys.maxMsSeen` watermark on first use. Standalone and fully tested — not yet wired into any existing time-gated service (see the task's `## Quyết định` for the scope reasoning); an optional `TrustedTimeSource` seam lets a caller force-reconcile past a quarantine when a confirmed trusted timestamp is available.
- Added `HapticChoreographer`/`HapticPattern` (IDEA-41): a small data-driven haptic sequencer on top of `fireHaptic` — `HapticPattern.reward`/`combo`/`error` presets (plus custom patterns, bounded to 16 pulses / 5s total for safety) play back pulse-by-pulse through an injectable timer. `play()` always cancels whatever pattern is still running first, so rapid re-triggering ("rage tap") never stacks multiple patterns' pulses on top of each other.
- Added a headless economy/balancing simulator, `tool/economy_sim.dart` (IDEA-36) — `dart run tool/economy_sim.dart` fast-forwards a scripted session pattern (sessions/day, energy spent/session) through `EnergyService`'s regen math and `OfflineProgressionService`'s earnings math, printing the resulting energy/currency curve across simulated days, no Flutter runtime required. Extracted the 2 services' pure formulas into `core/utils/economy_math.dart` (`regenEnergy`/`offlineEarnings`) so both the real services and the simulator call the exact same functions — verified by a cross-check test running both side by side against an identical timeline.
- `TutorialSequence`/`TutorialStep` (IDEA-35): data-driven tutorial authoring. `TutorialStep.listFromJson(json, keyRegistry: ...)` parses a JSON step list (the typical source: `RemoteConfigService.getString('onboarding_flow_v1')`) into `List<TutorialStep>` for the existing `TutorialSequenceController.start` — a designer can now reorder/reword/A-B-test onboarding without a rebuild. - Added `PurchaseLedgerService` (IDEA-33): a thin local cache for the 2 purchase shapes almost every game needs on top of `PurchaseSeam` — `grantConsumable`/`consume` for a balance that can never go negative (`consume` returns `false` instead of overdrawing), `grantPermanent`/`owns` for one-time unlocks.
