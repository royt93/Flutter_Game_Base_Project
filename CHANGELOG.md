## 0.2.0

- Added `QuestBoardPanel`/`QuestViewModel` (IDEA-44): the ready-to-use on-screen counterpart to `DailyQuestService` (IDEA-29), which previously had no widget consuming it. Shows a list of quests (label + progress bar + Claim button), same pure/data-driven convention as `LeaderboardList` — the caller maps its own `DailyQuestService` state into `QuestViewModel`s rather than this widget talking to the service directly. Claim is only enabled once a quest is completed and unclaimed; a quest crossing into that state at runtime pops its Claim button in with a small celebratory bounce (never replayed if already claimable on first mount), respecting `NeonTheme.reducedMotion`.
- Added `AchievementService.onUnlock` and `AchievementUnlockListener` (IDEA-43): `onUnlock` is a broadcast `Stream<String>` firing exactly once per achievement id the moment `incrementProgress` pushes it from not-completed to completed (never from `register`, even if a newly-declared threshold is already retroactively met; never again on further increments). `AchievementUnlockListener` wraps a subtree and shows a `ToastBanner` for every unlock — the first widget in the kit to actually consume `AchievementService`, which previously had none.
- Added `RemoteContentPack<T>` (IDEA-37): a typed, signed remote content slot for live-ops content (level definitions, shop catalogs, event schedules) built on `RemoteConfigService`'s asset-fallback-then-fetch pattern, `VersionedJsonStore`'s schema-version `migrate`, and `save_integrity.dart`'s HMAC signing. `load()` always resolves from the bundled asset first — never network-gated — then a `fetchRemote` fetch (if supplied) refreshes `current` in the background once it resolves. A fetched envelope with a bad/missing signature, a future `schemaVersion`, or a shape `fromJson` can't read is rejected silently, keeping whatever content was already applied — never crashes, never applies unverified content. A pack with no `contentSecret` configured never trusts a signed envelope at all (no key to check it against).
- `DebugQaOverlay` gained a Playground tab (IDEA-39) alongside its existing read-only state dump — a QA tester/designer can live-preview a `CommonButton` with an adjustable label, variant, and color directly on-device (long-press the corner, switch tabs), no rebuild needed.
- Added `TrustedClockService`/`classifyClockSample` (IDEA-40): a rewind-proof clock that also RECOVERS from a suspicious forward jump, unlike `utils/clamped_clock.dart`'s plain watermark (which permanently locks onto a far-future jump — deliberate or an honest clock misconfiguration — until the real wall clock naturally catches up, which for a big jump can be months or years). Classifies each new `ClockSample` (wall + monotonic reading) as normal/rewind/suspiciousForwardJump/reboot; a rewind or a quarantined jump never advances the trusted baseline, so it stays comparable against reality instead of a bogus reading. Migrates from the legacy `StorageKeys.maxMsSeen` watermark on first use. Standalone and fully tested — not yet wired into any existing time-gated service (see the task's `## Quyết định` for the scope reasoning); an optional `TrustedTimeSource` seam lets a caller force-reconcile past a quarantine when a confirmed trusted timestamp is available.
- Added `HapticChoreographer`/`HapticPattern` (IDEA-41): a small data-driven haptic sequencer on top of `fireHaptic` — `HapticPattern.reward`/`combo`/`error` presets (plus custom patterns, bounded to 16 pulses / 5s total for safety) play back pulse-by-pulse through an injectable timer. `play()` always cancels whatever pattern is still running first, so rapid re-triggering ("rage tap") never stacks multiple patterns' pulses on top of each other.
- Added a headless economy/balancing simulator, `tool/economy_sim.dart` (IDEA-36) — `dart run tool/economy_sim.dart` fast-forwards a scripted session pattern (sessions/day, energy spent/session) through `EnergyService`'s regen math and `OfflineProgressionService`'s earnings math, printing the resulting energy/currency curve across simulated days, no Flutter runtime required. Extracted the 2 services' pure formulas into `core/utils/economy_math.dart` (`regenEnergy`/`offlineEarnings`) so both the real services and the simulator call the exact same functions — verified by a cross-check test running both side by side against an identical timeline.
- `TutorialSequence`/`TutorialStep` (IDEA-35): data-driven tutorial authoring. `TutorialStep.listFromJson(json, keyRegistry: ...)` parses a JSON step list (the typical source: `RemoteConfigService.getString('onboarding_flow_v1')`) into `List<TutorialStep>` for the existing `TutorialSequenceController.start` — a designer can now reorder/reword/A-B-test onboarding without a rebuild. A step referencing an unknown `targetKey` name is skipped, never crashes. `TutorialStep` gained an optional `id`; when set, `TutorialSequenceController` logs `tutorial_step_shown`/`tutorial_step_dismissed` through `AnalyticsProvider` as the sequence advances (an imperative step with no `id` logs nothing, unchanged from before).
- Added `SeasonEventService` (IDEA-34): a repeating, has-a-time-window event/season schedule for `CountdownChip`. `currentWindow(eventId, {length, cooldown})` returns the same `SeasonEventWindow` (start/end) for repeated calls within one `length` + `cooldown` cycle, including across app restarts (anchor persisted per `eventId`), and never rolls a window back to an earlier cycle when the device clock is wound back (`ClampedClock`-backed).
- Added `PurchaseLedgerService` (IDEA-33): a thin local cache for the 2 purchase shapes almost every game needs on top of `PurchaseSeam` — `grantConsumable`/`consume` for a balance that can never go negative (`consume` returns `false` instead of overdrawing), `grantPermanent`/`owns` for one-time unlocks. Not a receipt-validation layer — meant to be called by the app's own `PurchaseSeam` adapter only after it has already verified a purchase.
- Added `ExperimentBucketingService` (IDEA-32): stable A/B-test variant assignment on top of `RemoteConfigService`'s flat key/value config. `variantFor(experimentKey, variants)` hashes a cached per-device anonymous id (generated once, never re-rolled) against the experiment key via a dependency-free FNV-1a hash, so the same device always lands in the same bucket for a given experiment across every app restart.
- Added `BackupRestorePanel` widget (IDEA-31): puts `StorageService.exportAll()`/`importAll()` and `save_integrity.dart`'s HMAC sign/verify on screen. Caller supplies `secret`, `onExport(signedJson)` and `onImport() -> signedJson?` seams (the actual file/QR/share mechanism stays app-specific, same convention as `CloudSaveProvider`); a checksum-mismatch or malformed import shows an inline error instead of crashing, and a restore is gated behind a confirm dialog since it overwrites the whole local save.
- Added `LocalScoreboardService` (IDEA-30): a local, single-device high-score table. `submitScore(playerLabel, score)` ranks a new submission against every previous one on the device (ties break by earlier submission); `topN(n)` returns `LeaderboardEntry` directly (rank + formatted score via `fmtNum`), ready to feed straight into `LeaderboardList` with no caller-side transform. Capped (default 50 rows) — lowest score dropped as soon as it would rank last.
- Added `DailyQuestService` (IDEA-29): a caller-declared daily/weekly quest tracker — the third reset-cadence mechanism alongside the permanent `AchievementService` and the fixed-calendar `DailyLoginService`. `register(id, targetCount, {period})` declares a quest once; `incrementProgress`/`isCompleted`/`claim` track it per `QuestPeriod` (`daily`/`weekly`), resetting automatically on the `ClampedClock`-backed period boundary so winding the device clock back can't re-claim an already-claimed quest.
- `RemoteConfigService` (ENH-58): partial remote responses now merge key-by-key on top of asset defaults instead of replacing the whole config (a response missing/omitting a key no longer wipes its asset fallback); added a read-only `snapshot` getter and a `source` getter (`RemoteConfigSource`: `assetOnly`/`remoteMerged`/`remoteFailed`) to inspect where the current config came from.
- Added reactive `EconomyWallet` with atomic earn/spend and transaction idempotency.
- Added `GameSessionController` for typed game session state, nested pause reasons and lifecycle bridging.
- Added typed `SdkResult` success/failure contracts for public service APIs.
- Added `SaveMigrationRegistry` for validated multi-hop save upgrades with copy-on-write migration.
- Added `AsyncActionGuard` for keyed single-flight and ordered exclusive actions.
- Added the GetX lifecycle coordinator for ordered, isolated background/resume hooks with storage flush and audio handling.
- Added a deterministic consumer contract-test fixture and bootstrap verification harness through the public package entrypoint.
- Core services: `ClampedClock`-backed cheat-proof offline earnings (`OfflineProgressionService`), `VersionedJsonStore`, `PerformanceTierService`, `DailyLoginService`, `EnergyService`, `CrashReporter` seam, plus reduced-motion support (`NeonTheme.reducedMotion`) applied across every animated widget in the kit.
- Widget kit grown from 21 to 40 widgets: new progress/reward widgets (`CountdownChip`, `PaginatedDotsIndicator`, `CoinFlyOverlay`, `DailyLoginCalendarWidget`, `EnergyBar`), new layout/card widgets (`RibbonBadge`, `ShopItemCard`, `VictoryCardTemplate`, `LeaderboardList`), new feedback/overlay widgets (`ConfettiOverlay`, `FloatingComboText`, `NetworkStatusBanner`, `ShimmerPlaceholder`, `SpotlightOverlay`), a game-specific `LevelSelectGrid`, and a game-feel/juice set (`SquashStretch`, `ScreenShake`, `ComboHeatBackground`).
- New Flame starter template (`RoyGame`) and `FlameTrackedOverlay` for pinning Flutter widgets to in-game world positions.
- Notable bug fixes: Flame camera-anchor/world-origin mismatch (BUG topLeft anchor), `ClampedClock` rewind resistance extended to `VersionedJsonStore`, several real-device narrow-width `RenderFlex` overflows (`CurrencyCounter`, `LevelSelectGrid`), `CommonButton` height rebalanced, `RewardPopup`'s lazily-initialized burst controller.
